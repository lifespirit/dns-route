# Импорт доменов и внешние источники

[English version](domain-import.md) · [К README](../README.rus.md)

В `dns-route` есть два независимых механизма списков:

1. **Special domains** определяют, какие A/AAAA-ответы запускают создание маршрутов.
2. **DNS records** создают локальные A, AAAA или NODATA-ответы и не отправляют такие запросы upstream.

Добавление имени в один список не добавляет его автоматически в другой.

## Общие правила CSV

Оба импортера:

- принимают UTF-8 и необязательный UTF-8 BOM в первом поле;
- используют стандартные правила CSV quoting;
- удаляют пробелы по краям полей;
- игнорируют пустые строки;
- игнорируют строки, первое поле которых начинается с `#` или `;`;
- отклоняют весь импорт при ошибке в любой значимой строке;
- ограничивают содержимое 32 МиБ;
- приводят имена к нижнему регистру и удаляют конечную точку.

У web-upload есть небольшой дополнительный лимит для multipart overhead сверх 32 МиБ содержимого CSV.

## CSV специальных доменов

Специальные домены — список выбора маршрутов.

### Допустимые строки

В каждой непустой строке одна значимая колонка:

```text
example.com
*.example.net
```

Допустим header `domain` или `pattern`:

```csv
domain
example.com
*.example.net
```

Дополнительные колонки разрешены только если они пусты:

```csv
example.com,
```

Следующая строка будет отклонена:

```csv
example.com,comment
```

### Семантика совпадений

```text
example.com
```

совпадает с:

```text
example.com
www.example.com
a.b.example.com
```

А:

```text
*.example.com
```

совпадает только с поддоменами и не включает apex `example.com`.

### Поведение постоянного импорта

Upload CSV специальных доменов:

- добавляет новые шаблоны в `special_domains`;
- включает уже существующий duplicate;
- игнорирует повторы внутри файла;
- **не удаляет** постоянные шаблоны, отсутствующие в файле;
- транзакционно активирует полученную конфигурацию.

Для удаления старых постоянных шаблонов используйте кнопку удаления или офлайн-обслуживание базы.

### Экспорт

Экспорт содержит включённые постоянные строки из `special_domains`, отсортированные по шаблону. Данные внешних источников не экспортируются.

## CSV локальных DNS-записей

Этот CSV управляет локальными authoritative A/AAAA/NODATA-ответами.

### Допустимые формы

```text
test.lan
test.lan,
test.lan,A
test.lan,AAAA
test.lan,A,
test.lan,AAAA,
test.lan,A,192.0.2.10
test.lan,AAAA,2001:db8::10
```

Значение:

| Строка | Результат |
|---|---|
| `test.lan` | NODATA одновременно для A и AAAA |
| `test.lan,` | То же, что одна колонка |
| `test.lan,A` или `test.lan,A,` | NODATA только для A |
| `test.lan,AAAA` или `test.lan,AAAA,` | NODATA только для AAAA |
| `test.lan,A,192.0.2.10` | Статический A-ответ |
| `test.lan,AAAA,2001:db8::10` | Статический AAAA-ответ |

Допустим header, в котором первые поля — `domain,type` либо `name,type`.

Поддерживается от одной до трёх колонок. Значение A обязано быть IPv4, AAAA — IPv6.

### Wildcard-записи

Имя может начинаться с wildcard:

```csv
*.ads.example,A
*.ads.example,AAAA
```

Такое правило совпадает с поддоменами, но не с самим `ads.example`.

### Несколько адресов

Повторите строки для одного имени и семейства:

```csv
service.lan,A,192.0.2.10
service.lan,A,192.0.2.11
service.lan,AAAA,2001:db8::10
```

Повторяющиеся одинаковые адреса игнорируются.

### Порядок строк внутри файла

Для каждого имени и семейства действует детерминированный последний режим:

- NODATA заменяет все ранее собранные адреса семейства;
- адрес после NODATA снова включает адресный ответ;
- следующие отличающиеся адреса добавляются.

Пример:

```csv
service.lan,A,192.0.2.10
service.lan,A
service.lan,A,192.0.2.20
service.lan,A,192.0.2.21
```

Итог: `192.0.2.20` и `192.0.2.21`.

### Поведение постоянного импорта

Для каждого имени из загруженного файла dns-route сначала удаляет все постоянные A и AAAA строки этого нормализованного имени, а затем вставляет импортированные семейства.

Следствия:

- имена, отсутствующие в файле, не меняются;
- если для имени указан только A, старые AAAA тоже удаляются, потому что замена выполняется целиком по имени;
- импортированные строки получают `ttl=0`, то есть используют текущий `local_record_ttl`;
- изменение базы и runtime-активация выполняются транзакционно.

### Экспорт

Экспорт содержит только включённые постоянные записи. Данные внешних источников не включаются.

Когда A и AAAA одновременно NODATA, используется компактная строка с одной колонкой. Остальные семейства выводятся отдельными строками.

## Внешние источники

И специальные домены, и DNS-записи можно загружать из внешних источников.

Поддерживаемые адреса:

```text
https://example.net/list.csv
http://192.168.1.10/list.csv
file:///etc/dns-route/list.csv
/etc/dns-route/list.csv
relative/path/list.csv
```

Поддерживаются URL schemes `http`, `https` и `file`. Значение без scheme считается filesystem path.

### Snapshot-модель

Содержимое внешнего источника разбирается в неизменяемый snapshot в памяти. Оно никогда не копируется в `special_domains` или `dns_records`.

Добавление или изменение источника меняет только его конфигурацию. Новое содержимое остаётся pending до успешного **Reload sources**.

Обычный **Reload config**:

- перечитывает SQLite;
- повторно использует активные snapshot;
- не читает source-файлы и не выполняет HTTP-запросы.

**Reload sources**:

1. загружает все включённые DNS-record sources;
2. загружает все включённые special-domain sources;
3. разбирает все файлы;
4. строит полную candidate-конфигурацию;
5. одновременно активирует все новые snapshot.

Если хотя бы один источник не скачался, не открылся или не разобрался, продолжают действовать предыдущие snapshot.

### Порядок и приоритет

Источники специальных доменов складываются: применяются все шаблоны активных sources и постоянные строки SQLite.

Источники DNS records образуют слои по ID в базе:

1. более ранний внешний источник;
2. более поздний источник переопределяет то же имя/семейство;
3. включённые постоянные записи SQLite применяются последними и имеют окончательный приоритет.

Источник переопределяет только явно указанное семейство. Пропущенное семейство остаётся от нижнего слоя.

## Режим источника `NO_DATA only`

У каждого DNS-record source есть опция **NO_DATA only**.

При включении:

- учитываются только первые две CSV-колонки;
- третья и последующие колонки игнорируются;
- строка с адресом становится NODATA-правилом выбранного семейства.

Например:

```csv
tracker.example,A,203.0.113.10
```

обрабатывается как:

```csv
tracker.example,A
```

Этот режим удобен для публичных blocklist: адресные значения источника никогда не станут DNS-ответом.

Одноколоночная строка по-прежнему блокирует и A, и AAAA.

## Пример blocklist в стиле Pi-hole

```text
# tracking domains
tracker.example
ads.example
telemetry.example
```

При импорте как DNS records каждое имя получает NODATA для A и AAAA. Это не перенаправление на `0.0.0.0` или `::`, а `NOERROR` с пустой секцией Answer.

При импорте того же файла как **Special domains** эффект совершенно другой: DNS-ответы остаются обычными, но полученные адреса маршрутизируются.

## Совместный пример

### `special-domains.csv`

```csv
pattern
example.org
*.media.example.net
```

### `dns-records.csv`

```csv
name,type,value
router.lan,A,192.168.1.1
router.lan,AAAA,fd00::1
ads.example,A
ads.example,AAAA
*.telemetry.example,A
*.telemetry.example,AAAA
```

Результат:

- `example.org` и его поддомены запускают маршрутизацию;
- у `media.example.net` маршрутизируются только поддомены;
- `router.lan` отвечает локально;
- `ads.example` и поддомены telemetry получают NODATA.

## Автоматизация с локальными файлами

Создайте файлы, доступные пользователю сервиса:

```bash
sudo install -d -m755 /etc/dns-route
sudo install -m644 special-domains.csv /etc/dns-route/special-domains.csv
sudo install -m644 dns-records.csv /etc/dns-route/dns-records.csv
```

Добавьте в панели:

```text
/etc/dns-route/special-domains.csv
/etc/dns-route/dns-records.csv
```

После замены файла нажмите **Reload sources**. При полном старте сервиса настроенные sources загружаются, но обычный config reload специально использует текущие snapshot.

Для автоматического обновления сначала скачивайте во временный файл, затем делайте atomic rename и refresh:

```bash
curl --fail --output /etc/dns-route/list.csv.new https://example.net/list.csv
mv /etc/dns-route/list.csv.new /etc/dns-route/list.csv
curl --fail -X POST http://127.0.0.1:8080/record/sources/refresh
```

Перед автоматизацией HTTP POST защитите admin endpoint.

## Диагностика импорта

### `CSV contains no ...`

Файл содержал только пустые строки, комментарии или header.

### Неверное число колонок

Special domains требуют одну значимую колонку. DNS records поддерживают максимум три, кроме источника в режиме **NO_DATA only**, где поздние колонки намеренно игнорируются.

### После импорта пропало старое семейство DNS

Постоянный DNS-import заменяет обе группы A и AAAA для каждого имени из файла. Включайте в CSV все семейства, которые должны сохраниться у этого имени.

### Новый внешний источник отображается pending/not loaded

Нажмите **Reload sources**. Добавление источника не выполняет I/O внутри транзакции конфигурации.

### Refresh завершился ошибкой, но старые данные остались

Это ожидаемая атомарность. Исправьте проблемный source и повторите **Reload sources**.

## Безопасность

- Рассматривайте удалённый CSV как полноценную DNS- и routing-конфигурацию.
- Предпочитайте HTTPS и доверенных издателей списков.
- Изменение списка специальных доменов при включённом Team Cymru может направить через туннель крупные префиксы.
- DNS-record source способен подавлять или заменять разрешение имён.
- Файловые sources открываются с правами демона; ограничьте возможность изменять их location и содержимое.
